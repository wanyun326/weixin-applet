# 「家庭点菜」小程序审核提交材料

> 更新时间：2026-11-27 / 对应当前审核版本
>
> 本文用于微信公众平台「版本管理 → 提交审核」和后台「用户隐私保护指引」。后台字段或字数限制如有变化，以后台页面为准。

## 一、直接复制到后台

### 小程序简介

```text
家庭点菜是一款仅面向家庭成员内部使用的用餐协作工具，成员可通过邀请码加入私密家庭，共同点菜、同步做菜进度，并记录餐后文字与照片；支持按月龄查看家庭辅食参考。
```

### 本版本功能说明

```text
支持创建或加入私密家庭、家庭成员共同点菜、同步待准备/已准备状态、通过微信好友发送家庭邀请码、自定义菜单与菜品图片、餐后文字和照片记录、历史当餐查看、宝宝档案及按月龄辅食参考、宝妈餐分类与菜品搜索。本版本不包含餐厅点餐、外卖、支付、配送、广告、朋友圈分享、公开广场或陌生人社交功能。
```

### 审核备注

```text
审核老师您好，本小程序仅供家庭成员内部协调用餐，不提供餐厅点餐、外卖、支付或配送服务，也没有商户入驻和公开交易。用户使用微信身份直接进入，无需账号密码。

创建或通过邀请码加入私密家庭后，成员可共同点菜、同步做菜状态，并自愿填写餐后文字和上传照片。宝宝辅食与宝妈餐内容属于一般菜谱参考，不提供疾病诊断、治疗或个性化医疗建议。

小程序仅允许通过微信好友发送家庭邀请码，不提供朋友圈公开分享。未创建家庭或未获得邀请码的用户无法查看任何家庭内容；家庭数据由云函数校验当前用户 OpenID 与家庭关系，非家庭成员不能读取。程序没有公开广场、内容推荐、陌生人搜索、关注、评论或私信。

测试路径：首次进入填写昵称 → 创建家庭 → 进入「点菜」开始新的一餐 → 点选任意菜品 → 打开「菜单」标记为已准备 → 点击结束当餐并保存记录 → 在「历史当餐」查看；辅食路径：底部「成员」→「宝宝管理」→ 添加宝宝 → 返回「辅食」。昵称、头像、餐后照片均为测试可选项，不会主动读取用户相册。
```

### 服务类目建议

首选尝试「工具 > 效率」；如果后台没有该子类，选择最接近的「效率工具 / 生活工具」，以后台可选列表为准。

不要选择「餐饮平台、外卖、点餐交易、商城」类目：本小程序没有餐厅、商户、支付、配送或订单交易。也不建议主动选择「医疗健康」类目：程序只提供普通家庭菜谱参考。

## 三、审核测试路径

无需测试账号和密码。审核人员使用自己的微信即可从空数据开始测试；开发调试卡片只在开发版显示，正式审核版本不会展示。

1. 首次打开，填写任意测试昵称；头像可选。
2. 点击「＋ 创建 / 加入家庭」，创建「审核测试家庭」。
3. 进入「点菜」，点击「开始新的一餐」。
4. 搜索菜品或切换分类，点选 2 道菜，确认「本餐已点」显示菜名和状态。
5. 进入「菜单」，把一道菜一键标记为「已准备」，确认已准备菜品没有删除按钮。
6. 点击「结束这一餐」，填写测试文字和一张照片，或点击「直接结束」跳过照片。
7. 回到「点菜」→「历史当餐」，展开餐次查看菜品和记录。
8. 辅食测试：进入「成员」→「宝宝管理」→ 添加约 20 个月月龄的测试宝宝 → 返回「辅食」，查看四类推荐并点击「换一道」。

邀请码流程为可选测试：成员页可复制邀请码，也可通过微信好友发送带邀请码的邀请卡片；第二位用户主动确认加入后，两位成员共享菜品、点菜结果和做菜状态。小程序不提供朋友圈分享，也不会向陌生人展示家庭内容。

## 四、用户隐私保护指引填写参考

必须在微信公众平台后台完成隐私保护指引配置。建议按实际收集范围勾选并填写以下用途，后台字段以后台为准。

### 微信昵称、头像

```text
用于在家庭成员列表中展示用户身份，让同一家庭成员能够识别点菜人和操作人。昵称由用户主动填写，头像由用户主动选择；不读取通讯录，不用于广告或对外展示。
```

### 用户选中的照片

```text
用于用户主动设置菜品图片或记录餐后留影。小程序只在用户点击添加图片后读取其主动选择的照片，仅用于当前家庭菜单和餐后记录，不会在用户未操作时读取相册。
```

### 家庭成员、宝宝和用餐信息

```text
用于实现家庭点菜协作和辅食参考，包括用户填写的家庭名称、邀请码、宝宝昵称/性别/出生日期，以及菜品、点菜状态、餐后文字和操作记录。上述信息仅在当前家庭内展示。
```

### 微信用户标识（OpenID）

```text
用于区分微信用户、校验家庭成员身份和隔离不同家庭的数据，不作为手机号或公开账号展示，不用于广告画像。
```

### 存储、共享和删除

```text
数据存储于微信云开发环境，仅在用户加入的家庭范围内共享，不向第三方出售或提供。普通成员可退出家庭；家庭创建人可解散家庭并清理关联数据；宝宝档案、自定义菜品和自定义辅食可在页面内删除。
```

后台要求填写客服联系方式时，请填写能够及时处理用户咨询、隐私申请和内容投诉的邮箱或客服电话，不要填写不必要的个人敏感身份信息。

## 七、审核追问答复模板

### 为什么不选餐饮类目？

```text
本小程序没有餐厅、商户、菜单交易、桌号、支付或配送，只服务于已有家庭成员之间的吃饭计划和做菜分工，因此属于家庭效率工具，不属于餐饮平台。
```

### 为什么需要照片权限？

```text
照片仅用于用户主动更换菜品图片或保存餐后留影，目的是记录家庭当餐内容；用户可以直接结束当餐而不上传任何照片，小程序不会在后台读取相册。
```

### 辅食和宝妈餐是否属于医疗健康服务？

```text
不属于。相关内容是普通家庭菜谱与饮食搭配参考，不进行疾病诊断、治疗、用药指导或个体化医疗建议。页面已提示特殊情况按医生或营养师建议调整。
```

### 为什么需要邀请码？

```text
邀请码用于建立私密家庭空间并隔离不同家庭的数据。没有公开广场、陌生人搜索或公开动态，只有持有邀请码并主动加入的用户才能看到对应家庭内容。
```

## 八、当前仍建议补强的审核风险

1. **用户生成内容安全**：自定义菜名、描述、图片和餐后照片属于用户生成内容。当前仅在私密家庭内可见；如审核明确要求，建议增加微信内容安全检测并保存检测结果。
2. **已结束餐次的单条删除**：当前家庭创建人可解散家庭并清理关联数据，但已结束餐次的单张照片和单条记录暂无单独删除按钮；如平台对删除权要求更严格，建议补充该入口。
3. **母婴文案边界**：避免使用「催奶、治疗、调理疾病、保证恢复」等功效承诺，保持「菜谱参考、均衡饮食、特殊情况遵医嘱」的定位。
